# F-010: Numeric style colors depend on process culture

Status: Closed
Priority: High
Area: Style Evaluation
Related concerns:
Related hypotheses:
GitHub Issue:
Confidence: High

Summary:
Style.ParseColorString uses ambient-culture double.Parse for RGB/HSL components.

Conclusion:
The same style can produce different opacity or throw under different locales.

Evidence:
- Our 3a263ea, VectorTileRenderer/Style.cs:690-725, inspected 2026-09-07.
- Uncached runtime probe of rgba(100,150,200,0.5): en-US alpha 127, de-DE alpha 251,
  fr-FR FormatException. RGB is unchanged in successful cases.
- [Fork evaluation](../Ststeiger-Fork-2026-09-07.md) links the fork's explicit
  InvariantCulture parsing and records the probe method and limitations.

Impact:
Style output depends on the consuming application's locale. The color cache can
conceal a later locale change; it does not fix initial parsing.

Scope:
Shared style evaluation used by CPU/GPU and all consuming projects.

Recommendation:
Use invariant culture for numeric color strings. Add fresh-style regressions for
RGB/HSL decimals and alpha under en-US, de-DE and fr-FR. Restore test culture after
each case and keep test isolation explicit.

Suggested refactor items:
R-004 style evaluation work in the existing refactor plan; this is a bounded fix.

Open questions:

Notes:
Reproduced only the RGBA example above. Other decimal branches are source-confirmed
risks, not separately reproduced. No production fix included in this evaluation.
