# F-001: GPU selection lacks a host lifecycle and verified readback

Status: Confirmed
Priority: High
Area: GPU / Hosting
Related concerns:
Related hypotheses: H-001
GitHub Issue:
Confidence: High

Summary:
The factory wraps GRContext.CreateGl without creating a native host context. The original global Auto cache and unchecked readback defects are now fixed locally; production host/thread ownership and image parity remain unresolved.

Conclusion:
Selecting Gpu/Auto does not prove hardware drawing. The isolated GPU harness proves hosted GPU drawing. The [validated production fixes](../Gpu-Failure-Fixes-2026-09-05.md) now check readback and retry Auto probes, with hardware regressions; this does not complete production hosting.

Evidence:
- VectorTileRenderer/CanvasFactory.cs:14-56; VectorTileRenderer/SkiaGpuCanvas.cs:11-72; VectorTileRenderer/Renderer.cs:197-235.
- [2026-09-05 runtime experiment](../Gpu-Validation-2026-09-05.md): RTX 4070 Ti hardware surface/readback, cached negative Auto probe, and an abandoned-context bitmap with failed checked readback.

Impact:
Stale Auto availability and silently unsuccessful readback were reproduced and mitigated locally. Without a captured render-thread context, a yielding provider still leaves the GL owner thread; the harness guard rejects access before native drawing.

Scope:
Factory, GPU canvas, async renderer and Mapsui host.

Recommendation:
The remaining pixel mismatch is now isolated under [F-009](F-009.md); see its
backend-rasterization evidence and acceptance-policy limits.
Use a host-owned context and explicit thread/lifetime contract; report actual surface backend and readback success. Validate fallback independently.
