# F-001: GPU selection lacks a host lifecycle and verified readback

Status: Confirmed
Priority: High
Area: GPU / Hosting
Related concerns:
Related hypotheses: H-001
GitHub Issue:
Confidence: High

Summary:
The factory wraps GRContext.CreateGl without creating a native host context. Auto caches the first availability result globally, while GPU surface creation can later fall back.

Conclusion:
Selecting Gpu/Auto does not prove hardware drawing. ReadPixels returns a success flag that is ignored; no dedicated GPU activation/parity tests were found.

Evidence:
- VectorTileRenderer/CanvasFactory.cs:14-56; VectorTileRenderer/SkiaGpuCanvas.cs:11-72; VectorTileRenderer/Renderer.cs:197-235.

Impact:
Possible silent CPU fallback, stale availability across hosts, or invalid output on failed readback. Actual runtime failure was not reproduced.

Scope:
Factory, GPU canvas, async renderer and Mapsui host.

Recommendation:
Use a host-owned context and explicit thread/lifetime contract; report actual surface backend and readback success. Validate fallback independently.
